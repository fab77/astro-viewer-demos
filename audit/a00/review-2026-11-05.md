## TAP clarification

A00 already imports `TapService` and `parseVOTable` from installed `astrospatial-services/astronomy/tap` 0.1.1. It posts ADQL to `https://sky.esa.int/esasky-tap/tap/sync`, parses the VOTable and passes real returned rows/column metadata to a viewer catalogue. JSON fallback is explicitly labelled; the subsequent JSON and CSV demonstrations intentionally use local fixtures. The review captured a real POST and **HTTP 503** from ESASky. The application correctly showed LOCAL FALLBACK. The final test asserts the query and branches on the actual response: TABLEDATA + LIVE for success, explicit LOCAL FALLBACK for service error. It does not intercept or mock the service. The earlier delivery had a successful live response; this review cannot claim a new live success.

## Architecture and ensureLayer

See [ROADMAP.md](../../ROADMAP.md) for verified package dependency diagrams and planned A12 Sesame, A13 HiPS node, A14 TAP tutorials. The service clients already exist, while these focused demos and architecture animations are planned next work. No sibling repository is changed.

`ensureLayer` caches layer aliases, deduplicates matching URLs and initially hides the new layer. This is demo orchestration, not public viewer API. A possible upstream URL-reuse primitive needs a separate contract for concurrency, cancellation, ownership and restore/disposal; the current captions show `addHiPSFromUrl`, `setActiveHiPS`, `changeColorMap` and `setHiPSOpacity`.
